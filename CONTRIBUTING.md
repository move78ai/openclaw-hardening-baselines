# Contributing

## Scope
We accept improvements that make the baseline safer and easier to execute, without turning this repo into a “platform.”

Examples:
- clearer docs and diagrams
- safer defaults in compose and proxy configs
- additional drift checks with low false positives
- examples for common environments (Linux VM, Docker, reverse proxy)

## How to contribute
1. Fork the repo
2. Create a branch: `feature/<name>` or `fix/<name>`
3. Make changes
4. Open a PR with:
   - what risk it reduces
   - what environments you tested on
   - any breaking changes

## Security
Do not open public issues for exploitable vulnerabilities. Use `SECURITY.md`.
